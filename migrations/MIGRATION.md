# Hermes VPS Migration — master plan

**Operational plan of record: `abxba-org/vps-migration-contabo`** (target: Contabo EU,
`vps-contabo`, 8GB/100GB; fresh provision + selective state copy; vault DATA-copy, never
rebuild; old box stays live until explicit operator GO). This repo's `migrations/` is the
artifact kit that plan calls: vault export/import scripts, host snapshot, guided restore.
Where the two differ, the Contabo plan wins (e.g. dedicated `hermes` user uid 1003 layout,
§3.4 write-freeze data copy; `export-vault.sh`/`import-vault.sh` here are the equivalent
one-shot bundler of that same data-copy semantics).

Migration of the full Hermes + agent-vault stack from the OVH VPS
(`vps-1558ffa7` / `vps-ovh.tail95f2ee.ts.net`) to a new VPS.

## What does NOT transfer (manual, in order of criticality)

1. **Vault state** — credentials, 34 service rules, audit logs, CA. Move the EXACT
   vault: `migrations/agent-vault/export-vault.sh` → `import-vault.sh`
   (see `migrations/agent-vault/VAULT-MIGRATION.md`). Unrecoverable-by-design:
   restic password and any key only inside the vault must be confirmed present.
2. **~/.hermes/.env secrets**: OPENROUTER_API_KEY (vault-injected placeholder — wire-env.py
   regenerates), SLACK_APP_TOKEN, SLACK_BOT_TOKEN, AGENT_VAULT_ADDR/TOKEN/VAULT,
   proxy + CA paths (regenerated by wire-env.py).
3. **~/.hermes/auth.json** — OpenRouter credential pool entry.
4. **Host secrets**: ~/HEVY/.hevy_env (HEVY_API_KEY), ~/.restic_password,
   git/gh auth, tailscale node identity, ~/.composio toolkit auth (re-link anyway),
   Grafana remote-write key (in alloy config — re-set on new box).
5. **Runtime state (NOT transferred by choice)**: state.db chat history, sessions/,
   kanban.db, pastes/, images/, logs/, terminal-sessions/. Rebuilt fresh. If chat
   history is wanted, copy state.db manually before decommission.
6. **Reinstalled by installer (never copy)**: hermes-agent source, tools/ (1.7G),
   installs/, environments/, lsp/, all caches.

## Restore order on the new VPS

```
1. base: ubuntu user, tailscale up, ufw/fail2ban basics
2. vault:    migrations/agent-vault/import-vault.sh      (Option A exact move)
3. hermes:   curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash
4. config:   gh auth login && gh repo clone abxba-org/hermes-config /root/hermes-config
             rsync -a /root/hermes-config/ ~/.hermes/    # (or /home/hermes/.hermes)
5. secrets:  re-enter .env values (SLACK_*, HEVY, RESTIC), run upstream/scripts/wire-env.py
6. gateway:  upstream/scripts/hermes-gateway.system-unit + nftables av-hermes (uid match!)
7. host extras: crontab.txt, gitconfig, HEVY clone, composio link, alloy re-point
8. verify:   gateway live in Slack, vault request log shows proxied calls, cron ticker runs
```

Full detail: `migrations/restore-new-vps.sh` (guided), `migrations/agent-vault/VAULT-MIGRATION.md`.
